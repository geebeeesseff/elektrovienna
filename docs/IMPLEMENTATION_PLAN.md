Implemented and **live validated for the current historical inventory on 2026-10-02**. The narrow `archive [--limit N]` command operates on existing eligible Phase 1 inventory only. It acquires raw/RFC822 messages and actual attachment bytes, including explicit inline-part handling, through the existing read-only Gmail adapter. No categories, classification, extraction or later-phase folders/behavior are introduced.

Immutable files are published beneath the exact authorized Knowledgebase root in `00_raw/gmail/` and `00_raw/attachments/`, using deterministic source-identity paths, actual SHA-256/byte lengths, and no silent overwrite. Files are durable before completion records; interruptions resume by verification/adoption. Already recorded files are integrity-checked on rerun. Inaccessible source bytes and integrity conflicts stop explicitly with sanitized errors.

Acceptance evidence: `tests/test_archive.py` covers root/path guards, synthetic raw/attachment persistence, hashes/provenance, idempotency, conflicts, interruption, file-before-state recovery, limits, eligible coverage and schema 1 migration. `tests/test_gmail_archive.py` covers raw bytes, attachment endpoints, exact inline/root-part matching, malformed data, zero-byte leaves, safe errors, pacing and retries.
